# AutoInfo 产物质量问题的根因分类分析

## 说在前面:三个问题源

用户(2026-08-17)提出关键问题:审查中发现的问题,根因到底是什么?
1. 大模型生成能力的随机性?(自然语言模型输出不可预测)
2. 没有内建的检查和审核机制?(管线无验证护栏)
3. 其他?(代码 bug / 数据源 / 配置)

## 核心洞察

**绝大多数"看着像 LLM 随机性"的问题,深层根因都是"管线缺少内建护栏",而不是模型本身不可控。**
LLM 输出天然会有噪声(幻觉、空响应、格式漂移),但**可观察、可检测、可在下游拦截**——问题在于 AutoInfo 的管线把 LLM 输出当"可靠输入"直接消费,没有在每一层加验证。

## 三类根因的归类统计

| 根因类别 | 问题数 | 代表 |
|---------|--------|------|
| ① **LLM 随机性**(表层) | 4 | 幻觉年份/幻觉断言/空 summary/空响应 |
| ② **缺内建护栏**(深层,承接①) | 4+ | 无溯源门/无日期校验/无空过滤/无摘要重试 |
| ③ **代码 bug / 其他** | 7 | #293/#295/#296/#297/#292/#291/#286 |

**关键结论**:②不是 ①的平行类别,而是①的**真正根因**。
"LLM 随机性"是触发条件,但**问题之所以能流到最终产物,是因为管线假设 LLM 输出可靠,没有护栏**。
如果加了三层护栏(产物后校验 / 处理层重试标记 / 采集层过滤),LLM 随机性不会造成可观察缺陷。

## 建议

单拎一个系统性 issue:【体系】AutoInfo 产物质量护栏缺失——LLM 输出被当可靠输入直接消费
- 定义三层护栏:L1 采集过滤 / L2 处理重试标记 / L3 产物后校验(日期/溯源/空检测)
- 关联所有单点 issue(#279/#293/#294/#286 等)作为该体系的实例
- 验收:构造 LLM 极端输出(幻觉/空/格式漂移),护栏必须拦截
