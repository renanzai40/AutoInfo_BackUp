# Demo Package 生产流程复盘(2026-08-17)

## 一、流程执行概况

目标:3 旗舰域 × 8 产物,全部重采重做,质量底线=end user 愿付费。
实际:247 条 fresh raw(逐条审核)、24 产物、899KB 交付包。耗时约 4 小时(含多次修复)。

## 二、各环节的痛与提升空间

### 1. 采集环节

| 痛点 | 详情 | 提升空间 |
|------|------|---------|
| 多 --source 静默缺源 | #296:3 源一起传只采 1 个 | 修复 CLI;采集后自动核对 per-source 数量 |
| fulltext 抓取被 403 | #292:web.py 无 UA | 修复;或采集前统一探测源可达性 |
| 反爬/网络屏蔽 | WSJ 屏蔽、seeking-alpha 部分 403 | 源注册表标注"受限源";备选源自动切换 |

| **教训**:采集不是一次性跑完,要**小批 + 人工抽验**再放大(先 dry-run 单源,确认质量再批量) |

### 2. 质量审核(本次耗时最长的环节)

| 痛点 | 详情 | 提升空间 |
|------|------|---------|
| 逐条审核靠关键词+人工 | 38 条噪声初筛漏掉(混杂命中词) | **审核脚本化**:deals 分类检测、语言检测、域关键词双向校验 |
| content 过短 | RSS abstract 135-300c,trafilatura 提纯后 3000c+ | 采集时直接 fulltext(修 #292 后);或审核脚本标出短条目 |
| 空 summary 传播 | #294:14 空行 | 修复管线;审核时扫 `|  |` 空表格行 |
| 幻觉年份 | "July 2023"×9 | **产物后处理**:扫描 >2026 年份 + 与 raw 日期交叉验证 |
| **教训**:审核要有**两层**——结构性(空/短/格式)+ 内容性(相关性/幻觉),前者可全自动化,后者抽样深读 |

### 3. 处理环节(process → KB)

| 痛点 | 详情 | 提升空间 |
|------|------|---------|
| database locked | #295:并行丢 29 条 | 修复;process 前检查是否有其他进程 |
| 串行执行慢 | 3 域 × 12-15 分钟 | 串行是安全选择;锁修好后可并行 |
| 无进度反馈 | 后台跑 15 分钟无输出 | CLI 加进度条/日志 |
| **教训**:process 是 LLM 密集环节,要在**确认采集质量后**一次跑好,避免反复 |

### 4. 产物生成环节

| 痛点 | 详情 | 提升空间 |
|------|------|---------|
| 日志污染产物 | #293:10/24 文件 | 修复 CLI stdout 隔离 |
| 产物落盘不一致 | digest 需 --persist,report/tutorial/presentation 只回显 | **统一 --out 落盘语义** |
| 生成慢无反馈 | 每个 30-165s | 进度提示 |
| audience 校验不一致 | #297 | 修复统一 |
| **教训**:产物生成要**批量 + 自动落盘 + 自动后处理**(清日志/扫年份/过滤空行),再人工抽验 |

### 5. 组包环节

| 痛点 | 详情 | 提升空间 |
|------|------|---------|
| 手工组装 | 脚本组装,但 manifest/zip 手动 | **一键脚本**:build_deliverable + manifest + zip + HTML 自动化 |
| HTML 演示文档 | 手写模板 | 后续复用/模板化 |
| **教训**:组包应该一次成型,反复打包(本流程打了 4 次)是前期质量问题传导 |

## 三、流程级改进建议(跨环节)

### 1. 建立"质量门 + 自动化审核"两层体系
- **自动化层**(脚本):结构检查(空/短/格式)、幻觉扫描(年份/实体/来源)、源相关性评分、空 summary 检测
- **人工层**:抽验 10-20% 产物全文 + 关键域深读
- 本次人工逐条审核 247 条是必要的(护住底线),但可先跑自动化筛,人工只需看被标记的

### 2. 生产流程模板化
- 建立 `scripts/produce_demo_package.py`:采集→审核→process→产物→组包 一键跑,每步输出质量报告
- 本次所有步骤都是手工命令行拼接,易漏易错

### 3. 失败可重试性
- process 的 database locked 损失要可恢复:失败清单 + `--retry-failed`
- 产物生成失败(空响应)要可恢复:失败清单 + 重生成命令

### 4. 数据链路工具
- **trace_id 端到端**:raw → KB entry → 产物断言 的可追溯校验工具(本次靠人工核对 URL)
- 自动生成"每产物 × 覆盖条目 × 溯源率"报告,交付时附上

### 5. 源生态管理
- 源健康度监控(403/网络屏蔽/API 退役如 uspto)
- 自动备源:主源失败 → 备源替换,sources.yaml 注册表化

## 五、下次生产直接可用的改进(本次教训落地)

1. **采集**:单源小批量 → 抽验 → 批量;每源独立跑(--source 单传)
2. **审核**:先自动化脚本筛 → 人工只看标记项;短 content 直接 trafilatura 提纯
3. **process**:串行跑(锁修复前);跑前检查无其他 process
4. **产物**:批量生成 → 自动清日志 → 扫年份/空行 → 人工抽验 20%
5. **组包**:一次成型(build script),交付附溯源报告
