# Demo 包发布标准(Definition of Done)

> 目的:把"项目什么时候算完成"从感觉变成**可打勾的检查表**。
> 判定:以下 4 条全部 ✅ = demo 状态达到生产端完备,可进入交付/存档;任何一条 ❌ = 未达标,只处理该条,不扩大范围。

## 标准 1:交付物通过独立全量审查

- [ ] 外部独立审查(非本管线/非自审)对交付包**全量**复审(16 文件级,非只看 diff)
- [ ] 结论:0 P0/P1/P2 缺陷(或 P2 已修复并复验)
- [ ] 审查报告归档(报告本身是交付物的一部分)

**已验证**:R5(1) 通过 ✅(2026-09-03,0 P0/P1/P2)

## 标准 2:连续 2 次新鲜单次生产在稳定带内

- [ ] 每次:单次生产(不重跑、不择优),跑完整 QC
- [ ] L0 gate:无真实缺陷(全部 flag 可裁决为良性/误报)
- [ ] L1 battery:无 P1+ 类;P2/P3 可裁决或有登记
- [ ] 已知缺陷类定向检查:截断/粘连/汇率/URL/占位 = 0
- [ ] **连续 2 次**结果同质(第 2 次不是碰运气)

**当前进度**:R6 样本 1/2 ✅(L0 干净、L1 仅 1 条可裁决语义项);R7 样本 2/2 ⏳

## 标准 3:残余风险登记表当前有效

- [ ] `docs/known-limitations/demo-quality-residuals.md` 存在且覆盖当前已知类
- [ ] 本轮 review/单次生产暴露的任何新类**已登记**(登记先于修复)
- [ ] 每类标注检测层 + 严重度 + 状态

## 标准 4:仓库与协议干净

- [ ] main 干净、0 open issues(或全部有 owner 与计划)
- [ ] AGENTS.md 三层 QC 协议(L0 gate → L1 battery → 外部 review)现行有效
- [ ] 单次生产纪律 + 修复闭环(issue → 修 → 重生成 → 全 QC)文档化

---

## 验收后的事(不是"完成",是"发布状态")

1. 交付包 = 最新通过标准 1 的版本(当前:R5(1))
2. 后续再生成 = 按 AGENTS.md 协议走完整 QC,产出达标即作为新交付,不达标按登记表处理
3. 内容过期/换模型/加功能 → 触发"系统变化"流程:重跑样本 + 更新登记表
