## 3. Dynamic content update loop (playbook §3) — AutoInfo commands

```
[any doc/code change]
   → python3 scripts/doc_inventory.py          # regenerate inventory
   → python3 scripts/doc_inventory.py --check  # exit 0 = facts consistent
   → fix what it flags (deterministic, no LLM)
   → commit
```

**The 7 drift-prone facts** (checked README ↔ AGENTS ↔ skill): MCP tools **146**
/ CLI groups **31** / delivery channels **13** / validation scenarios **138**
(65 functional + 73 regression) / demo domains **21** / LLM-required tools **16**
/ test count **~4925**.

**Additional facts to keep consistent manually** (not checker-gated): source
types 29, collector handlers 30, output templates 8, REST port 8741, schemas 4.

**Re-run protocols already defined in-repo:**
- `best-practice-review.md` §8 — refresh sources + scriptable audits per feature wave.
- `validation-scenario-contract.md` — scenario authoring + execution contract.
- `docs/dev/plans/README.md` — promote completed major-wave plans to `docs/dev/plans/`.

## 4. Skill synchronization (playbook §4) — AutoInfo mechanism

- `doc_inventory.py --check` reads `.opencode/skills/doc-manager-skill/SKILL.md`
  and verifies its 7 numbers match README — **skills cannot drift silently**.
- Dev skills (`.opencode/skills/`) are coding-agent procedures; operator skills
  (`docs/skills/`) are direct-user-agent procedures — keep the split clean.
- Editing a skill = editing a doc: regenerate inventory + run `--check` after.
